# 架构

```text
当前一个 NapCat / QQ 账号（QQ 侧永久只读）
            │
            └── HTTP-SSE：所有群的新事件
                            │
                            ▼
                    qq_mcp_server
       ┌────────────────────┼─────────────────────┐
       │                    │                     │
  SQLite/WAL          人物卡 XLSX 副本       私有规则 SQLite FTS
  消息/缺口/账号/笔记    每群一张当前卡          三本 PDF 离线构建
       │                    │                     │
       └────────────────────┴─────────────────────┘
                            │
              ┌─────────────┴─────────────┐
              ▼                           ▼
      /mcp/admin                 /mcp/groups/{group_key}
       跨群管理 App                 永久绑定一个已授权群
              │                           │
       群访问 / 账号切换            准则 / 卡 / 笔记
       缺口 / XLSX / NapCat         消息 / 规则 / 变更
       浏览器二次确认                一小时只读模组面板
```

## 账号、群与数据作用域

一个服务实例同一时刻只运行一个 NapCat 账号。可以登记多个属于同一玩家的 QQ 号；每个
账号使用独立的 `/var/lib/qq_mcp_server/napcat/accounts/<QQ>/qq` 登录目录。切换前必须
通过一次性网页确认，宿主机停止旧 NapCat 后才启动目标账号。切换不复制 SQLite 或人物
卡，因此所有账号共享聊天记录、人物卡、笔记、变更和规则索引；已登记账号会作为同一
player 的 QQ 别名。目标账号必须加入全部已启用跑团群，验证成功才恢复 SSE。

一个群永久绑定一个模组和一张当前人物卡。授予 AI 访问时生成随机且不可变的
`group_key`。群级 MCP 端点从 URL 确定作用域，工具不接受群号或 `group_key` 参数，
避免模型误选群。管理端点和每个群端点都是独立 OAuth resource；撤销群访问后群端点
立即失效。

群访问授权和采集是两个概念：

- NapCat SSE 看到的所有群消息都会入库，以免后续授权时已经丢失上下文。
- 只有经一次性网页授权的群才能由管理/群 MCP 读取正文。
- `roleplay_enabled` 只控制跑团工具，不停止入库。

## 纯 SSE 采集与消息缺口

正常后台没有登录轮询、群列表轮询、成员列表轮询或历史轮询。`NapCatRuntime` 只持续
消费回环 HTTP-SSE，并保存会话、生命周期、心跳和连接错误。发送账号与采集账号相同，
因此 NapCat SSE 启用 `reportSelfMessage`，保证其他设备发出的本人群消息也能进入事件流。

群列表、群资料、成员列表和登录信息只在用户明确执行配置、诊断或账号切换验证时读取。
每次 OneBot HTTP 动作记录动作名、来源、结果和耗时，便于排查高频调用。

SSE 断线、心跳异常、应用非正常重启、人工暂停或账号切换会为所有已观察群登记时间缺口。
重新连接只关闭缺口区间，不自动查询历史。跑团上下文若与未解决缺口重叠会拒绝返回；
更早的未解决缺口和人工接受的未验证缺口会作为完整性警告返回。

历史接口只由用户明确批准的缺口修复使用：

- 全局单并发；
- 每 60 秒最多一页；
- 滚动 24 小时最多 30 页；
- 出错、达到预算或应用重启后自动暂停；
- 找到缺口前后边界才标记为已修复，否则标记为未验证。

消息唯一键为 `(group_id, message_id)`，重复 SSE 事件或修复分页依靠 SQLite 幂等去重。
只接受文字、`@` 和 reply ID；纯媒体保存为 `[未读取的媒体消息]`，不获取媒体 URL。

## 人物卡、团务数据与撤销

`cards.py` 只打开固定浅蓝色模板的 `人物卡` 工作表并检查锚点，解析身份、属性、
HP/SAN/MP、技能、武器、资产、背景、物品、经历、神话接触及单元格来源。群 MCP 签发
短期上传链接，网页只负责选文件、预览和确认。

`trpg.commit_turn_updates` 在同一事务中提交 JSON Pointer 人物卡操作和结构化笔记，并
校验 `expected_version`。机械数值更新必须引用本群真实 `source_message_ids`。每次提交
生成 `change_id`；如果后续变更触及同一字段或笔记，定向撤销会拒绝覆盖。

群 MCP 还可签发一小时有效、绑定单群的只读模组面板，查看 RP 准则、人物卡、笔记、
消息、缺口状态和变更，不提供 Web 编辑入口。

## 规则索引

`build-rules` 是唯一 PDF 入口，必须同时提供调查员手册、核心规则书和魔法大典。构建器
离线提取文本并创建 FTS5 trigram 索引，记录书名、页码、章节和 SHA-256。运行服务只读
查询索引，没有 PDF 上传、网络检索或服务器端 LLM。

## 代码模块

- `onebot.py`：固定只读动作集合、调用来源和耗时审计。
- `normalization.py`：文字、`@`、引用和未读媒体标准化。
- `store.py`：schema v4；群、消息、缺口、账号、人物卡、笔记、变更和能力链接事务。
- `runtime.py`：SSE 会话/心跳、群事件发现、人工探测、账号切换验证和诊断。
- `gaps.py`：人工启动、严格限速且重启暂停的缺口修复。
- `sync.py`：持久化采集熔断与兼容代码；正常应用启动不运行历史调度器。
- `cards.py`：固定 Excel 模板解析、预览、换卡策略和存储。
- `rules.py`：三本 PDF 的离线构建与运行期只读检索。
- `mcp_server.py`：中文管理/群工具、OAuth 和群路径隔离。
- `web.py`：群访问、账号登记/切换、人物卡、NapCat 跳转和恢复确认。
- `dashboard.py`：单群只读档案、分页、SSE 和缺口状态。
- `ai_instructions.py`：内置工具选择、安全和跑团规则。
- `cli.py`：配置、运行、状态、规则构建和 NapCat 安全配置。

项目没有 Dice Echo、TUI、TXT、任意 SQL、消息发送、关键词命令或后台队列。一个 Python
进程使用 SQLite WAL 与短事务同时服务 SSE 和 MCP。
