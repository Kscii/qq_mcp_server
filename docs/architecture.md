# 架构

```text
单个 NapCat / QQ 账号（QQ 侧永久只读）
            │
            ├── get_group_list / get_group_member_list
            └── get_group_info / get_group_msg_history
                            │
                            ▼
                    qq_mcp_server
       ┌────────────────────┼─────────────────────┐
       │                    │                     │
  SQLite/WAL          人物卡 XLSX 副本       私有规则 SQLite FTS
  群/消息/笔记/变更     每群只保留当前卡        由三本 PDF 离线构建
       │                    │                     │
       └────────────────────┴─────────────────────┘
                            │
              ┌─────────────┴─────────────┐
              ▼                           ▼
       /mcp/admin                 /mcp/groups/{group_key}
       跨群管理 App                 永久绑定一个白名单群
              │
       一次性最小 Web 页面
       白名单 / XLSX 上传确认
```

## 隔离模型

一个服务实例承载一个 QQ 账号和多个群。白名单加入时生成随机且不可变的 `group_key`；
QQ 群号只保存在数据库中。每个群端点从 URL 解析 `group_key`，群级工具完全没有群参数，
所有消息、人物卡、笔记、变更和成员角色查询都由端点确定作用域。

一个群永久绑定一个模组，不支持在同群切换模组。一个群有且只有一个当前玩家与一张当前
人物卡，可以有多个 KP 与骰娘。用户若同时跑多个团，为每个团建立 QQ 群，并让对应的
ChatGPT 对话只连接该群的 MCP 地址。这比每次工具调用传群名更可靠，也避免昵称重名和
模型误选群。

移出白名单会停止同步并令群端点失效。停用 `roleplay_enabled` 只锁定跑团读写工具，
`trpg.get_status` 仍可诊断，而且白名单消息继续同步。

## 同步与消息边界

`MultiGroupSyncManager` 周期性读取白名单并动态增删每群任务，共用并发上限。新群先抓
最近一页，使 App 尽快可用；随后向更早历史分页回填。分页游标、最近就绪和完整回填状态
逐群保存，重启后续传。消息唯一键是 `(group_id, message_id)`，重叠分页依赖 SQLite
幂等去重。

只接受文字、`@` 和 reply ID。混合媒体消息保留可读文字，纯媒体消息写成
`[未读取的媒体消息]` 并标记 `contains_unsupported_media`，不请求媒体 URL。撤回事件不
处理，已经同步的文本会保留。群聊正文在所有 MCP 输出中都标记为不可信证据，绝不能
成为管理指令或提示词。

## 人物卡、团务数据与撤销

`cards.py` 只打开 `人物卡` 工作表并检查固定模板锚点，解析身份、属性、HP/SAN/MP、
技能、武器、资产、背景、物品、经历、神话接触及单元格来源。上传必须由群 MCP 签发短期
一次性链接，网页只做选择文件、预览和确认。

替换同名人物默认保留可映射的动态值；换成不同人物默认清空动态团务数据。用户可以在
确认页明确选择保留或重置。服务器保存一份基础导入卡和当前动态卡，但对外只有一张当前卡。

`trpg.commit_turn_updates` 在同一 SQLite 事务中提交 JSON Pointer 人物卡操作和结构化笔记
操作，并校验 `expected_version`。来自 QQ 事件的机械数值更新必须引用当前群真实的
`source_message_ids`。重要线索先由 AI 向用户确认，再写笔记。每次提交生成 `change_id`；
`trpg.undo_change` 只撤销这一整次提交，如果之后的变更触及相同字段或笔记，会拒绝回滚。

## 规则索引

`build-rules` 是唯一 PDF 入口，且强制同时提供调查员手册、核心规则书和魔法大典。构建器
在本地提取文本、按页切块并创建 FTS5 trigram 索引，记录来源书名、PDF 页码、章节和
SHA-256；索引不复制 PDF 二进制。运行服务只以只读方式查询索引，没有 OCR、网络检索、
PDF 上传或服务器端 LLM。

## 代码模块

- `onebot.py`：固定读取动作白名单的 OneBot HTTP 客户端。
- `normalization.py`：文本、`@`、引用和未读媒体标记标准化。
- `store.py`：群注册表、消息、角色、人物卡、笔记、变更和能力链接事务。
- `sync.py`：最近优先、多群并发、断点历史回填。
- `cards.py`：固定 Excel 模板解析、预览、换卡策略和存储。
- `rules.py`：三本 PDF 的离线构建与运行期只读检索。
- `mcp_server.py`：管理/群 MCP 工具、OAuth 和群路径隔离。
- `web.py`：只有白名单与人物卡上传确认的能力链接页面。
- `ai_instructions.py`：内置工具选择、安全、符号和三候选跑团规则。
- `cli.py`：配置、同步、运行、状态、规则构建和 NapCat 安全配置。

没有 Dice Echo、TUI、TXT、旧数据库迁移、任意 SQL、消息发送、Redis、队列或后台任务
框架。一个 Python 进程通过 SQLite WAL 与短事务同时服务同步和 MCP。
