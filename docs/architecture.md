# 架构

```text
当前一个 NapCat / QQ 账号（QQ 侧永久只读）
            │
            └── 反向 WebSocket：所有群的新事件
                            │
                            ▼
              独立 collector（127.0.0.1:3001）
                            │
                            ▼
                    SQLite / WAL
       ┌────────────────────┼─────────────────────┐
       │                    │                     │
  API / MCP           人物卡 XLSX 副本       私有规则 SQLite FTS
  消息/缺口/账号/笔记    每群一张当前卡          三本 PDF 离线构建
       │                    │                     │
       └────────────────────┴─────────────────────┘
                            │
              ┌─────────────┴─────────────┐
              ▼                           ▼
      /mcp/admin                 /mcp/groups/{group_key}
       跨群管理 App                 永久绑定一个已授权群
              │                           │
       群访问 / 账号切换            准则 / 卡 / 笔记
       缺口 / XLSX / NapCat         消息 / 规则 / 变更
       浏览器二次确认                一小时只读模组面板
```

## 账号、群与数据作用域

一个服务实例同一时刻只运行一个 NapCat 账号。可以登记多个属于同一玩家的 QQ 号；每个
账号使用独立的 `/var/lib/qq_mcp_server/napcat/accounts/<QQ>/qq` 登录目录。切换前必须
通过一次性网页确认，宿主机停止旧 NapCat 后才启动目标账号。切换不复制 SQLite 或人物
卡，因此所有账号共享聊天记录、人物卡、笔记、变更和规则索引；已登记账号会作为同一
player 的 QQ 别名。目标账号必须加入全部已启用跑团群，验证成功才恢复事件采集。

一个群永久绑定一个模组和一张当前人物卡。授予 AI 访问时生成随机且不可变的
`group_key`。群级 MCP 端点从 URL 确定作用域，工具不接受群号或 `group_key` 参数，
避免模型误选群。管理端点和每个群端点都是独立 OAuth resource；撤销群访问后群端点
立即失效。

群访问授权和采集是两个概念：

- NapCat 事件流看到的所有群消息都会入库，以免后续授权时已经丢失上下文。
- 只有经一次性网页授权的群才能由管理/群 MCP 读取正文。
- `roleplay_enabled` 只控制跑团工具，不停止入库。
- `archived` 独立于白名单：归档群保留历史只读访问和被动入库，但停止 RP 与主动补偿。

## 被动采集、在线状态与消息缺口

NapCat 作为客户端主动连接回环地址上的反向 WebSocket collector。collector 只接收事件，
保存会话、生命周期、心跳和连接错误；API 更新不会重启 collector。发送账号与采集账号
相同，因此启用 `reportSelfMessage`，保证其他设备发出的本人群消息也能进入事件流。

collector 每 60 秒调用一次本机 NapCat 的 `get_status`。它只读取本地会话状态，不请求
QQ群列表、成员或历史。群列表、群资料、成员列表和登录信息只在用户明确配置、诊断，
或会话稳定恢复验证时读取。每次 OneBot HTTP 动作都记录动作名、来源、结果和耗时。

事件断线、离线、collector 非正常重启、人工暂停或账号切换会为所有已观察群登记时间
缺口。QQ 重新在线后先保持五分钟安静期并连续确认两次，再用一次 `get_login_info`
确认账号，并为本次登录生成新的会话代次。白名单且未归档的群会建立自动补偿任务，从
最新页开始使用仅属于当前会话的游标逐页向前查找；旧登录留下的游标永不复用。

跑团上下文和最近消息在离线时仍返回 SQLite 缓存，并附带 `qq_online`、
`event_connected`、`data_fresh`、`safe_to_roleplay`、`warning_codes` 和缺口。模型可以
回顾已有内容，但 `safe_to_roleplay=false` 时不得声称缓存是最新消息或据此继续实时 RP。

所有历史读取来源共享 SQLite 原子预算：

- 全局单并发；
- 每 60 秒最多一页；
- 滚动 24 小时最多 30 页；
- 达到预算后在当前会话内自动等待并继续；
- 游标失效只允许重新定位一次，重复失败立即暂停；
- 找到缺口前后边界才标记为已修复，否则标记为未验证。

`trpg.get_recent_messages(refresh=true)` 是显式的一页刷新，每群十分钟最多一次，且仍受
24 小时 30 页总预算限制。消息唯一键为 `(group_id, message_id)`，重复事件或修复分页
依靠 SQLite 幂等去重。
只接受文字、`@` 和 reply ID；纯媒体保存为 `[未读取的媒体消息]`，不获取媒体 URL。

## 人物卡、团务数据与撤销

`cards.py` 只打开固定浅蓝色模板的 `人物卡` 工作表并检查锚点，解析身份、属性、
HP/SAN/MP、技能、武器、资产、背景、物品、经历、神话接触及单元格来源。群 MCP 签发
短期上传链接，网页只负责选文件、预览和确认。

`trpg.commit_turn_updates` 在同一事务中提交 JSON Pointer 人物卡操作和结构化笔记，并
校验 `expected_version`。机械数值更新必须引用本群真实 `source_message_ids`。每次提交
生成 `change_id`；如果后续变更触及同一字段或笔记，定向撤销会拒绝覆盖。

群 MCP 还可签发一小时有效、绑定单群的只读模组面板，查看 RP 准则、人物卡、笔记、
消息、缺口状态和变更，不提供 Web 编辑入口。

## 规则索引

`build-rules` 是唯一 PDF 入口，必须同时提供调查员手册、核心规则书和魔法大典。构建器
离线提取文本并创建 FTS5 trigram 索引，记录书名、页码、章节和 SHA-256。运行服务只读
查询索引，没有 PDF 上传、网络检索或服务器端 LLM。

## 代码模块

- `onebot.py`：固定只读动作集合、调用来源和耗时审计。
- `normalization.py`：文字、`@`、引用和未读媒体标准化。
- `store.py`：schema v5；群归档、恢复任务、历史预算、消息和团务数据事务。
- `collector.py`：带 Bearer Token 的回环反向 WebSocket 事件入口。
- `runtime.py`：事件会话/心跳、在线状态机、渐进自动补偿、群成员事件和诊断。
- `gaps.py`：人工启动、严格限速且重启暂停的缺口修复。
- `sync.py`：持久化采集熔断与兼容代码；正常应用启动不运行历史调度器。
- `cards.py`：固定 Excel 模板解析、预览、换卡策略和存储。
- `rules.py`：三本 PDF 的离线构建与运行期只读检索。
- `mcp_server.py`：中文管理/群工具、OAuth 和群路径隔离。
- `web.py`：群访问、账号登记/切换、人物卡、NapCat 跳转和恢复确认。
- `dashboard.py`：单群只读档案、分页、事件链路和缺口状态。
- `ai_instructions.py`：内置工具选择、安全和跑团规则。
- `cli.py`：配置、运行、状态、规则构建和 NapCat 安全配置。

项目没有 Dice Echo、TUI、TXT、任意 SQL、消息发送或关键词命令。API 与 collector 是
两个 Python 进程，使用 SQLite WAL 和短事务共享数据；NapCat 的生命周期与二者分离。
